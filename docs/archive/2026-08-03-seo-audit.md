# SEO Audit — Edward Kubiak Portfolio

**Date:** 2026-08-03 · **Commit:** `5c80fc8` · **Site:** https://edwardkubiak.com
**Method:** CAST multi-agent fan-out — 8 read-only `researcher` agents across 5 dimensions
(Technical/Crawlability, Structured Data, Sitemap/Robots/RSS/Manifest, On-Page Content, Performance/CWV),
each finding severity-rated with `file:line` evidence. Key Critical/High claims independently
re-verified by the orchestrator before inclusion (see **Verification notes**).

---

## Overall assessment

The portfolio's SEO **fundamentals are strong** — clean semantic HTML with correct heading
hierarchy, healthy internal linking, valid `Person` JSON-LD, a self-healing sitemap, deferred
privacy-preserving analytics, good `robots.txt`, and a well-built (if under-used) per-route meta
hook. The gaps are not sloppiness; they cluster into three themes:

1. **One structural ceiling** — the SPA-on-GitHub-Pages rendering model returns a real HTTP 404
   to crawlers for every deep link, which caps indexing and makes social unfurls impossible for
   all project/about/resume/now URLs. This is the single most consequential finding.
2. **Infrastructure that exists but isn't wired** — per-route descriptions, the PWA manifest link,
   per-project OG images, and per-project structured data all have the plumbing already present or
   trivially addable; they're just not connected.
3. **Performance micro-regressions** on the landing route (LCP behind a lazy chunk + an opacity
   animation; a ~141 kB eager JS floor).

None of the "quick win" fixes require architectural change. The one strategic decision is whether
to adopt build-time prerendering (below), which resolves the structural ceiling and several other
findings in a single pass.

## Prioritized action list

Ordered by (impact × inverse effort). ⚡ = quick win (≤ ~15 min, low blast radius).

### P0 — Critical

- **C1 · SPA deep links return HTTP 404 to crawlers — indexing & social-unfurl ceiling.**
  The `rafgraph/spa-github-pages` trick (`public/404.html` + the decode script in `index.html:69-85`)
  means GitHub Pages returns a genuine **404 HTTP status** on the first request to *any* non-root
  URL. Non-JS crawlers (X/Twitter, LinkedIn, Facebook, Slack, Discord, iMessage) see a 404 and stop —
  **no social preview card is possible for any deep link**. Googlebot weights the initial status
  heavily, which can suppress indexing of every `/projects/:slug`, `/about`, `/resume`, `/now` URL
  regardless of how good the client-rendered meta is.
  **Fix (strategic):** adopt build-time static HTML generation (`vite-react-ssg`, or a custom
  `react-dom/server` prerender reusing the route list already centralized in
  `scripts/generate-sitemap.mjs`) so GitHub Pages serves a real `200` + correct per-route meta at
  each path. **This one change also resolves the non-JS halves of H1 (per-project OG) and the
  canonical/description gaps, and lets JSON-LD (H6) ship statically.** Moderate lift; highest payoff.

- **C2 · Per-route meta descriptions never set — 5 static pages share one description.** ⚡
  `ROUTE_META` (`src/App.jsx:31-37`) supplies only `title` + `canonical`; `useDocumentMeta` already
  accepts `description` (`src/hooks/useDocumentMeta.js:131`) but is never given one for static routes,
  so `/`, `/about`, `/projects`, `/resume`, `/now` all inherit the generic `index.html:12` description.
  **Fix:** add a `description` to each `ROUTE_META` entry — no hook change needed. Suggested copy in
  **Appendix A**.

- **C3 · PWA manifest is built but never linked.** ⚡
  `public/manifest.json` is fully populated (dark-theme colors, maskable icon) but `index.html` has
  **no `<link rel="manifest">`** — installability, themed splash, and the maskable icon set are inert.
  **Fix:** add `<link rel="manifest" href="/manifest.json" />` beside `index.html:33`.

### P1 — High

- **H1 · All 19 project `og:image` URLs 404.**
  `ProjectDetail.jsx:26` sets `og:image` to `/og/${slug}.png`, but `public/og/` contains only
  `og-image.png`. `scripts/generate-og-image.mjs` *can* render per-slug images but is **not wired into
  any npm script or `prebuild`**, so they're never generated. Every project's social card breaks (for
  JS-executing consumers; non-JS consumers are already covered by C1).
  **Fix:** either wire `generate-og-image.mjs` into `prebuild`/deploy to emit real per-slug images, or
  fall back `ogImage` to `/og-image.png` when the per-slug asset is absent.

- **H2 · ProjectDetail meta descriptions are 5–10× too long (up to 641 chars).**
  `ProjectDetail.jsx:24` reuses long-form body copy verbatim (CAST = 641, Compute Atlas = 608,
  looptrip = 605, misfire = 616 chars). Google truncates arbitrarily — often mid `brew install`.
  **Fix:** add a `summary` (≤160 char) field per project in `projects.js`; set
  `description: project?.summary ?? project?.description`.

- **H3 · Homepage LCP is delayed by a lazy chunk + an opacity-0 entrance animation.**
  The `<h1>Edward Kubiak</h1>` LCP candidate (`HeroSection.jsx:75`) lives in the lazy-loaded `Home`
  chunk (`App.jsx:16`, extra JS round-trip on the #1 route) **and** animates in from `opacity:0`
  with a 0.1 s delay + 0.5 s duration (`HeroSection.jsx:79`, `src/utils/motion.js`) — Chrome only
  counts LCP once painted opaque, pushing it ~200–600 ms later than DOM insertion.
  **Fix:** eager-import `Home` (keep other routes lazy); render the hero H1 at full opacity (skip its
  entrance animation) while keeping the rest of the fade choreography.

- **H4 · ~141 kB gzip eager JS floor before any route renders.**
  Real build (`npx vite build`): main `index-*.js` = 99 kB gzip, `motion-*.js` = 42 kB gzip. `motion`
  is `modulepreload`ed on every load (imported top-level in `App.jsx:4` for nav + page transitions),
  so its separate chunk aids caching but not first-load weight. `cmdk`/`CommandPalette` (a ⌘K feature
  most visitors never trigger) ships eagerly in the main chunk (`App.jsx:21,239`).
  **Fix:** `lazy()`-load `CommandPalette` behind its own `Suspense`; add `rollup-plugin-visualizer`
  (not currently present) to treemap the 309 kB main chunk; decide whether the motion-on-every-route
  floor is an accepted trade for the transition polish.

- **H5 · RSS feed items all carry a 1970 epoch `pubDate`.**
  `scripts/generate-rss.mjs:46` = `new Date(0).toISOString() // Placeholder`; confirmed in
  `public/rss.xml`. Readers sort/dedupe on `pubDate`; all-epoch ordering is undefined.
  **Fix:** derive real per-project dates (add `dateAdded` to `projects.js`, or `git log -1 --format=%aI`
  at generate time). *(Also reconsider whether RSS is warranted at all — see P2 / no blog.)*

- **H6 · No `WebSite`, `BreadcrumbList`, or per-project software schema.**
  Only the static `Person` block exists. 19 project pages carry zero structured data despite
  `projects.js` already holding `github`/`tech`/`link` to populate `SoftwareSourceCode` (open-source
  tools) and `SoftwareApplication` (live products like Compute Atlas). `BreadcrumbList` on
  `/projects/:slug` is high-ROI for SERP snippets. **Do not** add a `SearchAction` (no on-site search).
  **Fix:** add a static `WebSite` block in `index.html`; add a `useJsonLd` sibling hook (mirroring
  `useDocumentMeta`'s create-or-restore pattern) to inject `BreadcrumbList` + per-project schema — or,
  better, emit them statically if C1's prerender lands. Snippets in **Appendix B**.

### P2 — Medium

- **Title/role drift across the site.** `/` title says "AI **Engineer**" (`App.jsx:32`) while
  `index.html:35` + JSON-LD `jobTitle` say "AI **Systems** Engineer", and the nav masthead
  (`App.jsx:65`) says "**Software** Engineer" — three variants. Standardize on
  "Full Stack Developer & AI Systems Engineer" for entity consistency.
- **Sitemap `<lastmod>` is uniformly the build date** (`generate-sitemap.mjs:37`), so every URL
  appears to change daily (daily cron) — Google may ignore an untrustworthy `lastmod` entirely.
  Source real per-project dates (same fix as H5).
- **Fraunces display font is never preloaded.** Imported via JS→CSS (`src/index.jsx:5-6`), so the
  `.woff2` is discovered late on the critical path for the font-dependent LCP text. Add a
  build-time-injected `<link rel="preload" as="font" … crossorigin>` (needs a small Vite plugin
  because filenames are content-hashed).
- **GitHub stats/activity static JSON lacks local/committed parity.** *(Downgraded from a
  Critical false-positive — see Verification notes.)* `deploy.yml` (lines 56/72/145) **does** generate
  `public/github-stars.json` + `github-activity.json` at deploy, so the **live site does not hit the
  GitHub API per visitor.** But the files aren't committed / not in `prebuild`, so `npm run preview`
  and any non-deploy path fall through to live unauthenticated API (60 req/hr/IP), and the committed
  `last-known-commits.json` last-resort fallback is empty (`{"commits":[],"cachedAt":""}`).
  Mirror the `sync-*.mjs` pattern into a script + `prebuild` for parity, and seed the fallback.
- **RSS generator lives only in `deploy.yml`**, not in `package.json`/`prebuild` — no local repro and
  a stale committed `rss.xml`. Add an `"rss"` npm script; fold into `prebuild` alongside sitemap.
- **`Person` schema missing `image`** (recommended for rich results). Point at `og-image.png` interim,
  or add a real headshot later.
- **Homepage meta description vs `Person` description drift** — the meta copy is vaguer than the
  JSON-LD (which names CAST + Compute Atlas). Align the meta description (covered by Appendix A).

### P3 — Low / Nit

- Hero image (`public/media/compute-atlas.png`, 93 kB indexed PNG) has good CLS hygiene but no
  WebP/AVIF, `srcset`, or `decoding="async"` — low effort, only one on-page image.
- Repeated identical anchor text **"View plate →"** for 5 different Home links
  (`FeaturedWork.jsx:82,138,193`) — add per-link `aria-label`.
- `/resume` and `/now` are only reachable via primary nav — cross-link from body copy / ProjectDetail.
- Hardcoded `alt="… interactive map view"` (`ProjectDetail.jsx:117`) is accurate only for Compute
  Atlas — move alt into the project data model.
- `manifest.json` missing `description`/`id`; `start_url` is `"."` (use `"/"`).
- No Safari `mask-icon` (likely intentional — Safari dropped pinned tabs; note, don't chase).
- `changefreq` in sitemap is a legacy signal Google ignores — harmless, leave it.
- Fraunces `full-italic` (150 kB) may be near-unused — check whether any italic display text exists
  before paying for both axis files; the `full` (vs `wght`) variant is correctly *intentional*
  (design uses `opsz`/`SOFT`/`WONK` axes).
- No metric-matched font fallback → minor FOUT reflow; only worth `fontaine`/`capsize` if field CLS
  shows it mattering.

## Verification notes (orchestrator re-checks)

Two agent findings were adjusted after direct verification — recorded for transparency:

1. **"Dead RSS link" (initial suspicion): FALSE ALARM.** `/rss.xml` **is** regenerated on every
   deploy (`deploy.yml:407-408`), so it's not a 404. The *real* issue is the epoch-`pubDate` bug (H5)
   + local-parity gap (P2).
2. **"Live GitHub API on every homepage load = Critical" (perf-c): OVERSTATED → Medium.** The agent's
   grep for `node scripts/...` missed the inline `github.script`/`fs.writeFileSync` steps in
   `deploy.yml` (lines 56/72/145-146) that generate the static JSON. Verified present → the **live**
   site serves tier-1 static and does **not** hit the API per visitor. The residual issue is
   local/committed parity + an empty fallback file (P2).

`Person`-schema and `seo-performance` agents each drew a spurious `[CAST-TRUNCATED]` flag; both had
in fact relayed complete deliverables ending in `Status: DONE` — no data lost.
